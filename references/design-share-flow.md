# 设计分享 · Agent 自主流程

仅在当前任务选择 `design-share` 时执行。先读 `editorial-cover.md` 与 `creator-profiles.md`。本流程的头像、背景和截图布局规则优先；不执行 `agent-native-flow.md` 中 AI 教程专用的全图无人像、右下角头像预留和本地合成步骤。

## 执行方式

- 使用宿主实际提供、支持参考图的内置图像工具；工具不可用时说明限制，不自动改用收费 API 或本地拼图。
- 尊重用户本次指定方式，然后读取 `${OIL_COVER_CONFIG:-~/.oil-cover/config.json}` 的 `mode`。已有 `agent-native` 直接执行；未配置时说明此风格使用自主方式，不要求额外 Key，也不擅自保存全局偏好。
- 已设为或明确指定 `script` 时，说明现有脚本尚不支持此预设，取得本次采用自主方式的选择后再继续，不静默更改默认。
- 本预设不启用 `creator_portrait.enabled`，不调用 `--composite-base`；左上角小圆头像与其余封面内容在图像工具中一起生成。

## 按平台读取作者资料

1. 确定要用于哪些平台。用户已说小红书、公众号或抖音等时不重复问；未提供时询问。
2. 执行 `python <SKILL_DIR>/scripts/creator_profiles.py list`。首次使用某平台，收集准确名称和头像图片/本地路径，可一次提供多平台资料。已有完整资料直接复用，只问缺失项。
3. 使用 `set` 将原头像复制到本机资料目录。不同平台不静默串用；只有用户明确说明相同时才分别复用。多张头像归属不清时确认映射，不按上传顺序猜。通用 `default` 资料只在用户选择时使用。
4. 生成前实际执行 `show --platform ...`，将返回的 `display_name`、`signature`、`avatar_path` 写入方案并用于生成。不能只保存资料却继续使用示例作者。缺失头像只需补头像，不丢掉名称。

## 选取真实证据

- 先检查已有成图、风格、标题、资料和源文件；仅生成缺失或明确要求修改的版本。
- 有视频时先看首帧，再按字幕、时间线或可见操作选取 4–8 张候选。首帧若为片头、旧封面或纯文字标题页，不作主截图。选能证明结果的画面，不上传整段视频。
- 有字幕或文稿先通读；没有时根据实际可见画面和用户说明判断，不编造口播、制作过程或性能。记录主主题、主产品、承载界面、辅助品牌。
- 用户指定标题完整保留，只调整断行；未指定时提炼准确结果或动作。明确“一眼看到的结果”、主证据、辅助证据、可删除内容；不要为了展示完整工作区把主证据缩小。
- 截图优先于 Logo；产品资产按 `product-assets.md` 核对，用户 Logo 使用真实素材，不拿次要品牌替代，不编造图标。

## 生成与检查

- 默认独立生成 3:4、4:3、16:9；多平台资料不同时分别生成，文件名带平台以避免覆盖。相同画面与相同署名可以复用。有额外发布尺寸要求时按用户要求适配。
- 先查看截图、Logo 和本次头像，再保存 `analysis.md`、`cover_plan.md`、每幅完整 `.prompt.md`。提示词明确逐词字体/字重/颜色、单色渐变终点、三种素材角色、准确署名、当前年份与比例。
- 显式将实际素材传给图像工具，不依赖历史对话猜参考图。作者头像作为左上圆形标记输入属于此预设的一部分；截图中无关人像或摄像头气泡仍需移除。
- 每幅独立调用，整张一次生成；不本地贴字、贴 Logo、拼截图或裁切凑比例。需要修改已生成图时使用内置图像编辑工具。
- 检查完整标题、产品归因、主证据、头像身份、名称、Logo、年份、单色背景和尺寸。因明确错误每个画幅最多自动返工一次；不因审美“还能更好”重复整套生成，再次失败时报告具体缺口。
- 最终图默认跟随源视频，工作资料放 `<视频名>.oil-cover/`；配置了 `video_library_root` 时沿用主入口的归位规则。宿主指定输出目录时遵循其约定。保留所用提示词与实际工具记录，不伪造返回字段。
- 修改时成套保留仍可用的旧图片和 sidecar，验收后再切换。用户明确选定版本后停止其他候选。

## 交付

给出三张图、实际像素尺寸、提示词与方案位置、参考素材及逐幅检查结论。内置工具只给近似比例时如实说明。明确头像作为生成参考输入，细节可能重绘；不套用 AI 教程的“头像未上传、仅本地合成”说明。账号配置、原头像、凭据和机器路径不进入公共示例。
